## 已确认的内容与发布范围

- 首版仅管理文章；独立页面后续设计。
- 单作者，无审稿流程；展示作者资料独立于后台登录用户。
- 文章工作稿与已发布版本分离，保存修改不影响线上内容。
- 按文章选择需要发布的修改，整体构建站点；其他文章的工作稿不得随构建上线。

## 已确认的编辑与组织规则

- DB 保存 Markdown 正文，后台提供源码编辑与渲染预览；首版不支持 MDX。旧 HTML 与 Markdown 扩展需兼容验证。
- 新文章提供可编辑 Slug 建议，首次发布前确定并检查唯一性，首次发布后冻结。旧中文和数字 Slug 保留；改 URL 与自动重定向后续设计。
- 分类与标签均为平面结构、可多选、可为空；分别管理，保留旧名称和对应 URL。
- 手动保存是明确操作；自动保存仅更新工作稿，不逐次生成历史。手动保存和发布保留不可变修订。
- 恢复旧修订只更新工作稿，不直接影响线上；首版不提供版本差异比较。
- 媒体范围为图片、附件上传、正文引用与封面选择；以 filemgmt 为存储基础。工作稿、历史修订和已发布版本引用的文件受删除保护。
- 保留旧 `/images/`、`/upload/` 地址的迁移兼容要求。

## 已确认的发布规则

- 构建完成且成功切换线上版本后，发布才成功；构建或切换失败时继续提供原站点，并展示错误原因。
- 同站点发布任务串行；任务开始时固定所选内容版本，后续编辑不混入本次发布。
- 重复请求返回同一任务；失败或中断后由作者明确重试，使用原来固定的所选内容版本。修改内容后应提交新任务。
- 重启后核实切换结果：已成功切换的任务补记成功，未完成的任务标记中断；持久化任务状态与错误记录。

- 官方依据：[组件文档](https://github.com/uiwjs/react-md-editor)、[依赖声明](https://github.com/uiwjs/react-md-editor/blob/master/core/package.json)。具体版本待实施时核实并锁定。
- 编辑器即时预览用于写作；另提供真实 Astro 页面预览，固定工作稿版本、仅后台认证用户可访问，不切换线上站点。编辑器预览不承诺与 Astro 输出完全一致。
- 接入验证覆盖中文输入法、长文、撤销重做、媒体插入、Markdown 输出兼容和现有设计体系样式。

## 已确认的生命周期与运行边界

- 支持文章下线与归档。下线通过发布任务更新站点，成功前旧内容继续可见。
- 归档保留正文、历史与 Slug，允许恢复；首版不提供永久删除。
- 首版不支持定时发布；文章展示日期可手动设置，未来日期不触发自动发布。
- 首版同机自托管：CMS 管理内容、独立 Builder 构建、Web 服务器提供静态站点；远端部署后续扩展。
- CMS 正常运行不依赖 Node；执行 Astro 构建的环境需要 Node。该边界不改变 Admin 嵌入 CMS、Astro 独立构建的约定。

## 已确认的配置、日期与媒体规则

- 站点配置范围：名称、简介、公开地址、语言、时区；作者资料范围：名称、简介、头像。
- 配置保存不直接上线，通过独立“发布站点配置”操作生效；文章发布使用已上线配置。主题切换、导航编排和高级 SEO 配置后续扩展。
- 分类与标签首次对外发布后冻结名称和 URL。尚未对外发布的项可改名；被工作稿、修订或已发布版本引用的项禁止删除。改名及重定向后续设计。
- 文章展示日期、草稿保存时间与实际上线时间分别记录。展示日期可编辑；旧文章保留原日期，新文章首次发布时默认采用本次发布时间；草稿保存不改变线上更新时间，再次发布才更新。
- 默认站点时区为 `Asia/Shanghai`。
- 构建时将需要的托管媒体纳入静态发布产物，提供稳定地址；静态站点及其图片附件不依赖 CMS API 在线。未发布内容的媒体不因上传而公开。
- 正文可保留外部链接；首版不自动下载或代理外部资源。

## 已确认的归档与保留规则

- 文章须成功下线后才能归档；归档内容退出默认列表并停止编辑。
- 恢复归档后重新进入可编辑状态，不自动上线；Slug 继续占用，禁止被其他文章复用。
- 首版永久保留文章修订，不自动清理引用媒体。
- 保留最近 5 次成功发布产物及当前使用产物；首版不提供整站一键回滚，文章恢复通过恢复修订并再次发布完成。

## 已确认的操作与渲染规则

- 同一文章多标签页编辑通过版本冲突检测阻止静默覆盖；自动保存同样遵守。冲突时保留本地未保存内容，供重新加载或人工合并。
- 允许保存不完整草稿；发布需要标题、唯一合法 Slug、非空正文及有效媒体引用。摘要与封面可选。
- 点击发布先保存当前内容并生成固定修订，再提交任务；保存失败则不发布。
- Astro 预览使用当前文章的所选工作稿版本，其他文章及站点配置使用线上版本；新文章也生成真实详情页。
- 首版站点提供文章列表、详情、分类列表、标签列表和 404，展示站点及作者基本信息。搜索、评论、RSS、主题切换和独立页面后续扩展。
- 支持标准 Markdown、GFM 表格、代码高亮、标题锚点。正文 raw HTML 转义为文字，围栏代码保留原样；公式、Mermaid 与可执行正文组件后续扩展。
- 编辑器与 Astro 共用语法约定，迁移时修正旧文章相对链接。

## 领域状态与不变量

文章生命周期、线上可见性和发布任务状态分别表达，避免用一个 `draft/published` 字段承担所有语义。

| 维度 | 状态/数据 | 约束 |
| --- | --- | --- |
| 文章生命周期 | active / archived | archived 不可编辑，恢复变为 active，不自动上线 |
| 当前内容 | 工作稿、工作稿版本号 | 保存不改变线上；版本号用于冲突检测 |
| 线上可见性 | 当前 release 是否包含文章及其修订 | 只有成功切换改变；下线后仍保留上次发布记录 |
| 内容历史 | 不可变修订 | 恢复写入工作稿，不修改旧修订 |
| 发布任务 | queued / running / succeeded / failed / interrupted | 单站点串行；失败不改变当前 release |
| 预览任务 | queued / running / succeeded / failed / interrupted | 私有产物；不推进发布记录或首次发布锁定 |

“有未发布修改”由工作稿与线上快照的可编辑字段比较得出，不以保存时间判断；后台可同时显示“线上可见”和“有未发布修改”。

归档要求文章已不在当前线上 release 中，且没有正在排队或执行的该文章发布操作；并发下线、发布、归档不得绕过该约束。未上线文章可以直接归档。

Slug 有非空值时在文章间唯一，归档不释放。单路径片段允许中文、数字与普通短横线名称，禁止路径分隔符、点路径、控制字符和编码路径绕过；实际路由编码只执行一次。首次成功上线才锁定，之后下线/归档也不能修改。排队和执行中的发布暂时锁定涉及的 Slug 与分类标签身份，避免构建快照与当前身份分叉。

首次成功发布锁定分类标签名称及 URL。修订包含当时名称快照：未发布分类改名不回写历史；若恢复的旧名称与已锁定名称冲突，明确报错并要求重新选择，不静默改变历史。

## 数据设计

以下为逻辑模型；SQL 类型、索引及数据库特定细节在实施任务中完成，SQLite/PostgreSQL 必须共享相同约束。

| 对象 | 核心数据 | 所有权 |
| --- | --- | --- |
| Article | 稳定 ID、Slug、首次发布锁定、归档状态、创建时间 | content |
| Working Draft | article ID、version、标题、Markdown、摘要、封面、展示日期、分类/标签、保存时间及操作用户 | content |
| Revision | article ID、序号、不可变完整内容快照、来源、创建时间及操作用户 | content |
| Category / Tag | 稳定 ID、名称、URL、首次发布锁定 | taxonomy |
| Media | 对应 filemgmt file ID、媒体类型、不可变资源身份、公开目标路径、旧路径别名 | media |
| Media Reference | 所属工作稿/修订/配置快照/待执行任务/保留 release，以及 media ID | media |
| Site Config | 单站点工作配置、version、不可变配置修订 | siteconfig |
| Publication Job | 操作类型、所选修订、幂等键、状态、请求摘要、错误、时间、操作者 | publishing |
| Publication Attempt | 所属任务、次数、基线 release、完整 manifest、执行阶段、错误、构建环境标识 | publishing |
| Release | attempt ID、完整 manifest、产物路径及校验信息、成功切换时间 | publishing |
| Site State | 当前 release ID、发布协调状态 | publishing |
| Preview Job | 所选修订、基线 release、状态、私有产物位置、错误 | publishing |

配置快照包含作者资料，不直接关联系统用户的昵称。操作用户用于审计，不作为对外作者。

Revision 快照冻结正文、标题、摘要、封面、展示日期及分类标签；媒体身份不可变，配置通过 release 指定。数据库是全部内容快照与发布选择的主数据源；产物 manifest 是数据库记录的派生部署凭据，不允许从生成 Markdown 反写内容。

自动保存事务检查工作稿版本号并同步媒体引用；手动保存追加不可变修订。恢复旧修订也检查版本号，只更新工作稿。点击发布在事务中保存当前工作稿、追加发布修订并持久化任务，事务失败不会留下已提交任务。

时间以 UTC 保存、按站点时区展示。未指定展示日期时，本次发布提交时间作为冻结的默认日期，重试不漂移；实际首次上线时间和最后上线时间只在成功切换时记账，线上更新时间使用该次成功发布记录。迁移保留旧展示日期及已有更新时间，不用导入时间替代。

## 模块与接口设计

Content 负责文章与修订，Taxonomy 负责分类标签，Media 在 filemgmt 上管理内容引用，Site Config 管理工作配置及快照。Publishing 协调任务与发布选择，Builder 只接受完整构建输入并返回产物，不读取实时工作稿、修改文章状态或处理 HTTP。

首版使用独立 Go Builder/worker 可执行进程读取持久化任务；CMS API 接受操作和查询任务，不在 handler/content service 启动 `npm`。不引入 MQ；发布任务和预览构建共用串行 worker，避免首版同机并行构建争用。独立进程重启不影响 API 基础服务。

全部业务 API 位于 `/api/v1/*`，沿用已有认证、会话与权限检查；系统 API 保持 `/api/system/*`。单作者不意味着匿名管理接口。逻辑接口如下，最终 DTO 沿用仓库现有响应风格：

| 操作 | API 草案 | 关键约定 |
| --- | --- | --- |
| 列表/新建/详情 | GET/POST `/api/v1/articles`；GET `/api/v1/articles/{id}` | 返回生命周期、线上状态与未发布修改标记 |
| 保存工作稿 | PUT `/api/v1/articles/{id}/draft` | expectedVersion；明确 manual/autosave；响应新版本及可选 revision ID |
| 修订列表/详情 | GET `/api/v1/articles/{id}/revisions`；GET `.../revisions/{revisionId}` | 修订只读 |
| 恢复修订 | POST `.../revisions/{revisionId}/restore` | expectedVersion；仅改变工作稿 |
| 发布文章 | POST `/api/v1/articles/{id}/publish` | 当前编辑内容、expectedVersion、Idempotency-Key；保存并固定修订，返回任务 |
| 下线 | POST `/api/v1/articles/{id}/unpublish` | 幂等键；成功切换前保持线上状态 |
| 归档/恢复 | POST `/api/v1/articles/{id}/archive` / `restore` | expectedVersion；校验线上与在途操作 |
| 分类/标签 | GET/POST `/api/v1/categories`、`/tags`；PATCH/DELETE `/{id}` | 锁定与引用保护；不提供文章永久删除 |
| 媒体选择/上传 | GET/POST `/api/v1/media`；GET/DELETE `/{id}` | 复用 filemgmt 服务；返回稳定身份和正文引用路径 |
| 工作配置 | GET/PUT `/api/v1/site-config` | expectedVersion；保存不发布 |
| 发布配置 | POST `/api/v1/site-config/publish` | 固定配置修订、幂等键；不带入文章工作稿 |
| 查询任务/重试 | GET `/api/v1/publication-jobs`、`/{id}`；POST `/{id}/retry` | 固定所选内容，追加执行尝试 |
| 提交/查询预览 | POST `/api/v1/articles/{id}/previews`；GET `/api/v1/previews/{id}` | 保存并固定快照；不锁定公开身份或更新线上 |
| 查看预览产物 | GET `/api/v1/previews/{id}/content/*` | HTML、资源和深层路由均需认证；不公开构建目录 |

保存冲突返回 409，校验失败按现有约定返回字段错误，任务创建返回 202。相同幂等键与相同请求返回原任务；相同键不同请求拒绝。提交和重试均审计。手动重试需要新幂等键，以区别新的执行尝试与网络重发。

后台 JWT 不会自动附加到 iframe/图片请求；私有预览通过认证 fetch 与受控资源加载实现，或使用限定到该预览路径的短期认证凭据。具体机制在接入任务验证，禁止为图方便公开草稿 URL，也不改变后台现有 JWT + DB Session 认证体系。

## 构建与切换算法

1. 提交操作时，在数据库固定目标文章修订或配置修订、幂等键及操作顺序；普通后续编辑不修改它。
2. Worker 获取站点执行锁，校验任务前提；以此时最新成功 release 为基线生成完整 manifest。发布文章替换该文章；下线删除该文章；发布配置仅替换配置。其余项目沿用基线。
3. 持久化 attempt 与完整 manifest；在独立运行目录生成 Markdown、配置与所需媒体，不改 `site/src` 中的源码，不消费未选工作稿。
4. 用固定站点模板和依赖构建；记录模板/依赖标识。检查路由、引用、产物完整性与可读性。生成失败不进入切换阶段。
5. 产物就绪后记录可恢复的切换意图，将 Web 服务器读取的当前 release 指针一次切换到完整产物；禁止覆盖正在提供访问的目录逐文件更新。
6. 在数据库事务中登记当前 release、目标文章/配置发布记录、身份锁定及任务成功。切换完成但登记前中断，恢复流程根据指针、attempt ID 和 manifest 校验结果补记成功。
7. 若指针仍为基线，则任务标记 interrupted，不自动重新发布；若指针结果不符合任何合法切换记录，则停止新的发布并报告人工处理，不凭猜测写成功。

DB 内容主数据源与部署指针的运行事实分工明确；无法用一个数据库事务覆盖文件系统切换，因此必须验证每个中断位置。文件指针只用于确认哪份派生产物已部署，不能创建或修改主内容。

明确重试固定目标内容，但重新使用最新成功 release 作为基线；不能把整个旧 manifest 重新上线，否则会撤回其他任务已经发布的内容。每次尝试均保留其实际基线。已成功任务不可重试；下线已下线文章等无效状态不额外生成构建。

重试前重新检查目标文章生命周期、Slug、分类标签身份和媒体有效性；旧快照与当前冻结身份冲突时拒绝并说明原因，要求作者修正工作稿并提交新任务，不偷偷替换原修订。执行锁取得后再次校验，避免提交与执行之间的竞态。

预览构建同样生成完整 manifest，覆盖当前文章，其余采用最新线上版本；产物存入私有 preview 目录，没有切换步骤。初次使用需先发布初始站点配置，生成无文章站点基线，再进入文章发布/预览流程。

## 静态媒体与运行目录

开发数据使用 `.runtime/`，生产数据位于仓库外。逻辑目录包含 uploads（私有源文件）、generated（任务输入）、releases（不可变正式产物）、previews（私有预览）、logs；公开 Web 根只指向当前成功 release，不公开运行数据根目录。

新托管媒体使用不可变资源身份及稳定站内路径，例如 `/media/<id>/<safe-name>`，覆盖原文件内容必须上传为新资源。旧图片与附件建立路径映射并保留 `/images/...`、`/upload/...`；多个路径可指向同一媒体身份。路径冲突必须报告，不能静默覆盖。

当前 filemgmt 的 `accessUrl` 为需 Bearer 认证的 `/api/system/file/<id>/view`，并非公开 URL；管理界面已有 `use-authenticated-file-url` 通过认证 fetch 生成 Object URL。编辑器即时预览采用同类适配，正文持久化稳定媒体路径，不保存 blob URL 或认证接口 URL。当前没有公开 uploads 挂载，继续保留私有源文件边界。

构建只导出 manifest 实际引用的媒体及已发布作者头像，递归检查 Markdown 图片、附件链接与封面。通过 AST 提取引用，不能将代码中的示例链接算作资源；外部 HTTP(S) 链接保留，不作为托管文件引用。旧相对文章链接在导入时解析到正式文章 URL；无法解析则报告。

工作稿、修订、工作配置/配置修订、在途任务、私有预览与保留 release 共同构成删除保护。保护必须覆盖所有底层删除入口及会使引用资源失效的停用操作；仅在新媒体页面禁用按钮不足以保证一致性。已公开媒体可能仍留在历史产物或浏览器缓存，下线不承诺撤回已经下载的数据。

已有文件删除为元数据软删除，停用不会阻止读取；Media 不得把停用解释为下线，或依赖磁盘文件还在而跳过引用保护。新增跨入口的引用检查保留系统文件原有软删除与状态语义，只对内容引用增加约束。服务器执行媒体权限校验，不能仅依赖前端按钮显隐。公开图片验证真实类型，附件以下载方式提供；站点资源响应不把上传的 HTML 当可执行正文页面。

产物清理只删除超出保留范围且不被当前指针、在途任务或恢复流程使用的正式 release；媒体源和文章修订不自动清理。私有预览/失败输入的清理按部署配置进行，并与私有产物引用同步，不允许绕过文件保护。

## 管理后台与站点

后台复用现有列表、表单、Dialog、权限和上传设计。文章详情页组合元数据表单、开源 Markdown 编辑器、自动保存状态、明确保存/预览/发布操作，以及修订与线上状态；媒体选择提供上传与已有资源选择。先检查现有页面 Pattern，编辑器页面若无法表达再记录例外。

自动保存采用防抖、每篇串行请求；显示保存中/已保存/失败/冲突。发布等待当前保存完成，上传未完成时不插入虚假路径。权限区分内容编辑、发布与配置管理，但首版默认同一作者使用，不引入审批或协作流程。

首版 Astro 模板使用独立输入契约，不直接读 CMS 数据库或访问管理 API。正式列表/分类/标签仅由 manifest 中的线上文章生成；下线文章从详情及全部聚合入口消失。标题锚点、代码高亮和语言标签纳入正文兼容验收；组件私有语法不自动进入站点语法契约。

## 验收标准

### 本阶段设计完成

1. 统一术语、产品边界、数据/接口/发布恢复设计和任务依赖齐备。
2. 已接受决策与待实施验证清楚区分；用户确认共同理解。
3. 不创建内容业务表、空模块或实现代码；不把本阶段设计完成等同首版系统已经实现。

### 后续实现必测场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 草稿保存/自动保存 | 不完整草稿可保存；自动保存不产生逐次历史；线上内容和更新时间不变 |
| 两标签页编辑 | 旧 expectedVersion 返回冲突；保留本地修改；自动保存也不覆盖 |
| 手动保存/恢复 | 修订不可变；恢复只改变工作稿；归档文章不可编辑 |
| A、B 同时修改，仅发布 A | A 使用所选修订，B 仍为旧线上内容；未发布配置也不混入 |
| 排队后继续编辑 | 任务仍发布原所选修订；工作稿保留后续编辑 |
| 请求超时后重发 | 相同幂等键返回同一任务/尝试，无重复发布 |
| 失败后其他任务成功再重试 | 重试保持所选内容但以最新线上基线构建，不撤回其他更新 |
| 构建/校验/切换失败 | 原站点、线上记录仍有效；错误可查询，可明确重试 |
| 每个切换中断窗口重启 | 指针未切换则 interrupted；已切换则补记成功；无半份公开站点 |
| 下线与归档 | 全部公开入口移除后才能归档；恢复不自动上线；Slug 不释放 |
| 身份与组织约束 | 旧中文/数字 Slug 可用；重复、编码绕过拒绝；首次上线后冻结分类标签 |
| 私有预览 | 新文章真实详情可预览；其他工作稿不混入；匿名页面/资源请求均拒绝 |
| 静态媒体 | CMS 停止仍能访问已发布媒体；上传未发布资源不公开；所有删除/停用入口执行引用保护 |
| 发布配置 | 仅配置上线，文章沿用线上版本；作者与登录用户名不绑定 |
| 数据库兼容 | SQLite 与 PostgreSQL 的 migration、唯一性、事务与冲突契约一致 |
| 构建解耦 | Astro 失败不阻止 CMS 构建/运行；Admin 失败不阻止独立 Site 构建 |

旧迁移另验：本地 95 篇文章的数量、正文、日期、多分类、标签与附件映射完整；公开文章 URL/旧媒体 URL 保持；GFM 表格、标题锚点、代码高亮及语言标签输出验证；相对文章链接修正；发现无法兼容内容时明确报告。旧站源若更新，先重新盘点后导入，不能把本地调查误认为线上真值。

## 实施验证事项

- 编辑器最终版本、React 19/中文输入法/长文/撤销行为及样式集成。
- JWT 会话下真实预览 HTML 与资源的认证机制。
