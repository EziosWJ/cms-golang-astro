## Problem Statement

博客作者目前只有系统管理后台和最小 Astro 工程，无法在 CMS 中撰写、预览、发布文章。旧博客依赖 Markdown 文件及原 GitHub 发布链路，尚无以 CMS 数据库为主数据源的内容工作流。

作者需要安全保存未完成的修改、明确选择要上线的内容，并在构建失败或服务重启时继续提供旧站点；迁移后已公开文章和媒体的地址及正文表达能力应保持。

## Solution

提供单作者文章管理闭环：后台编写 Markdown 工作稿、保存和恢复修订、选择分类标签与媒体、查看即时及私有 Astro 预览、明确发布。独立 Builder 在同机生成完整静态发布产物，切换成功才算上线。编辑工作稿、修改站点配置及其他文章草稿不会意外改变线上内容。

首版提供文章列表、详情、分类/标签页和 404。支持显式发布站点及作者配置、文章下线和归档，并以单向导入迁移旧内容。此 Spec 是已确认 Phase 1 设计的后续实施规格，不表示 Phase 1 已实现这些业务。

## User Stories

1. As a 博客作者, I want 创建文章工作稿, so that 我能开始撰写新文章。
2. As a 博客作者, I want 保存不完整草稿, so that 我不必写完内容才能保存进度。
3. As a 博客作者, I want 使用 Markdown 源码编辑器, so that 我能继续使用熟悉的文本写作方式。
4. As a 博客作者, I want 即时查看正文渲染, so that 我能发现表格和代码排版问题。
5. As a 博客作者, I want 使用中文输入法和撤销重做, so that 我能顺畅编辑长文章。
6. As a 博客作者, I want 看到自动保存状态及失败信息, so that 我知道修改是否已持久化。
7. As a 博客作者, I want 自动保存不不断生成历史记录, so that 手动修订历史保持可读。
8. As a 博客作者, I want 手动保存产生不可变修订, so that 我可以找回旧内容。
9. As a 博客作者, I want 查看并恢复旧修订到工作稿, so that 我能修正内容而不直接影响线上。
10. As a 博客作者, I want 多标签页编辑发生冲突时保留本地修改, so that 内容不会被静默覆盖。
11. As a 博客作者, I want 编辑已发布文章时保留原线上版本, so that 读者不会看到未完成的修改。
12. As a 博客作者, I want 看到线上状态和未发布修改, so that 我能判断是否需要再次发布。
13. As a 博客作者, I want 编辑首次发布前的 Slug 建议, so that 我能确定文章地址。
14. As a 博客作者, I want 已发布 Slug 保持稳定, so that 分享出去的链接继续有效。
15. As a 博客作者, I want 保留旧中文和数字 Slug, so that 迁移不破坏现有文章地址。
16. As a 博客作者, I want 为文章选择多个平面分类和标签, so that 我能延续旧博客的组织方式。
17. As a 博客作者, I want 分类与标签首次发布后名称和 URL 冻结, so that 聚合页面的链接保持稳定。
18. As a 博客作者, I want 被历史或当前内容引用的分类标签不能删除, so that 修订可恢复且引用不失效。
19. As a 博客作者, I want 上传图片和附件或选择已有媒体, so that 我能将资源插入正文。
20. As a 博客作者, I want 为文章选择可选封面, so that 我能补充文章展示信息。
21. As a 博客作者, I want 上传完成后再插入稳定媒体引用, so that 正文没有临时或无效地址。
22. As a 博客作者, I want 媒体被工作稿或历史修订引用时受到删除保护, so that 旧内容不会损坏。
23. As a 博客作者, I want 上传未发布资源保持私有, so that 草稿媒体不会自动公开。
24. As a 博客作者, I want 保留外部链接而不自动抓取它们, so that 首版写作行为清晰可控。
25. As a 博客作者, I want 查看真实 Astro 文章预览, so that 我能确认站点实际效果。
26. As a 博客作者, I want 预览只替换当前文章, so that 其他未发布修改不会混入。
27. As a 博客作者, I want 预览页面和所有资源都需要认证, so that 未发布内容不会泄漏。
28. As a 博客作者, I want 点击发布时先保存并固定当前内容, so that 上线内容与本次操作一致。
29. As a 博客作者, I want 发布前得到标题、Slug、正文与媒体校验错误, so that 错误内容不会进入构建。
30. As a 博客作者, I want 只发布选中文章而整体构建站点, so that 其他文章和配置工作稿不会顺带上线。
31. As a 博客作者, I want 提交任务后继续编辑, so that 构建等待不会阻止写作或改变已提交版本。
32. As a 博客作者, I want 查看持久化发布任务状态和错误, so that 我能判断上线结果。
33. As a 博客作者, I want 重复请求返回同一任务, so that 网络超时不会导致重复发布。
34. As a 博客作者, I want 明确重试失败任务且保留原选中内容, so that 重试不会意外上线新修改。
35. As a 博客作者, I want 重试以最新线上站点为基线, so that 不会撤回其他已成功发布的更新。
36. As a 博客作者, I want 构建或切换失败时旧站点继续运行, so that 发布错误不造成站点不可用。
37. As a 运维者, I want 重启后核实切换结果并恢复正确记账, so that 不会误报失败或公开半份站点。
38. As a 博客作者, I want 编辑站点名称、简介、公开地址、语言、时区及作者资料, so that 我能管理博客基本信息。
39. As a 博客作者, I want 站点配置通过独立操作上线, so that 保存配置和发布文章都不会顺带发布它。
40. As a 博客作者, I want 展示作者资料独立于登录用户名, so that 系统用户不被误当作文章作者。
41. As a 博客作者, I want 分开记录展示日期、保存时间和实际发布时间, so that 写作进度不会改变文章对外时间。
42. As a 博客作者, I want 下线成功后再归档并保留历史和 Slug, so that 移除文章不会丢失可恢复内容。
43. As a 博客作者, I want 恢复归档文章但不自动上线, so that 我能检查后再次明确发布。
44. As a 读者, I want 在列表、详情、分类和标签页面阅读已发布文章, so that 我能浏览博客内容。
45. As a 读者, I want CMS 停止时仍能访问静态页面、图片和附件, so that 阅读不依赖管理 API 可用性。
46. As a 读者, I want 文章下线后全部聚合入口都移除它, so that 我不会从列表进入失效文章。
47. As a 博客作者, I want 导入旧文章时保留 URL、日期、多分类、标签和媒体地址, so that 迁移不损失已有内容。
48. As a 博客作者, I want 导入前获得盘点、冲突和不兼容报告, so that 我能修正旧相对链接和数据问题。
49. As a 运维者, I want SQLite 和 PostgreSQL 具有相同业务约束, so that 我能按部署需要选择数据库。
50. As a 运维者, I want CMS、Admin 和站点构建保持解耦, so that Astro 构建故障不会破坏管理系统。
51. As a 运维者, I want 清理旧产物时保留最近五次成功发布及当前产物, so that 运行数据增长可控且在线站点不受影响。

## Implementation Decisions

- 沿用已接受架构决策：CMS DB 是内容主数据源，生成 Markdown 是中间产物，Git 只管理源码。Admin 嵌入 CMS 二进制，Astro 独立构建。API 启动和显式数据库迁移分离。
- 首版仅有文章、单作者、无审稿。系统用户用于认证与审计，展示作者资料包含于站点配置快照；部门不获得内容业务含义。
- Content 管理稳定 Article、Working Draft 和不可变 Revision；Taxonomy 管理平面 Category/Tag；Media 在 filemgmt 基础上管理资源身份与引用；Site Config 管理工作配置及配置修订；Publishing 管理任务、尝试、Manifest、Release 和当前站点状态。
- 文章生命周期 active/archived、当前工作稿及版本号、release 中的线上可见性彼此独立。“有未发布修改”按可编辑内容比较，不按保存时间判断。
- 手动保存和发布产生不可变完整修订，自动保存仅更新工作稿。保存和恢复采用 expectedVersion，过期版本返回 409；冲突保留本地修改。
- 不完整草稿可保存。发布要求非空标题及正文、唯一合法 Slug、有效媒体引用；摘要和封面可选。保存工作稿、创建发布修订和持久化任务在同一事务内完成，失败不提交任务。
- 集成开源 MIT 许可的 React Markdown 编辑器，首选 @uiw/react-md-editor；实施时锁定版本并验证 React 19、中文输入法、长文、撤销重做、工具栏与设计体系。复用已有文件上传及批量上传能力，不自研编辑器核心或重建上传服务。
- 后台沿用已有列表/表单/上传 Pattern 和权限体系；新增业务 API 使用版本化命名空间，旧系统 API 保留。服务器执行内容编辑、发布、配置及媒体权限校验，前端显隐不能替代鉴权。
- Slug 为单路径片段，允许历史中文和数字值，禁止路径分隔符、点路径、控制字符及编码绕过。非空值唯一，首次成功上线后冻结，下线和归档不释放。文章 URL 保持旧 archives 路由和尾斜线规则。
- 分类和标签分别管理，可多选可为空；首次成功发布后冻结名称和 URL。引用项不可删除。历史修订保存名称快照；恢复时与已冻结身份冲突须报告而非改写历史。排队及执行时保护涉及身份，重试重新检查前提。
- 正文支持标准 Markdown、GFM 表格、代码高亮、标题锚点和代码语言标签。raw HTML 转义，围栏代码原样展示；编辑器私有扩展不得自动进入站点语法。正文持久化稳定媒体路径，不保存 blob 或带认证的后台 URL。
- 媒体保持不可变身份；更新文件内容采用新资源。AST 提取正文图片/附件引用，不把代码示例当实际引用。封面、头像及工作配置引用同样记录。
- 工作稿、历史修订、配置快照、在途任务、私有预览和保留 release 共同保护媒体，所有删除入口都执行检查。保留原系统文件软删除及状态语义，停用不等于公开下线。
- 原文件访问接口需要 Bearer 认证，不能直接充当公开图片 URL。源文件继续私有；构建仅导出该 manifest 实际引用的媒体并由静态服务器提供。外部 HTTP(S) 链接保留，不自动抓取或代理；附件以下载方式交付。
- 首版同机自托管，使用独立 Go Builder/worker、数据库持久化队列和串行执行，不引入 MQ。Builder 接受固定完整输入并返回产物，不读取实时草稿或修改文章发布状态；HTTP handler/content service 不执行 npm。API 常规运行不依赖 Node，构建环境需要 Node。
- 发布提交即固定目标文章/配置修订。执行时以最新成功 release 为基线，发布文章仅替换该文章，下线仅移除该文章，发布配置仅替换配置。持久化每次尝试的完整 manifest 和构建标识，使用隔离运行目录。
- 构建和校验完成后，持久化切换意图并一次切换整个当前 release 指针，再登记成功。禁止逐文件覆盖在线目录。构建、校验或切换失败保留原站点；只有切换成功才推进线上记录和首次发布锁定。
- 同一幂等键和相同请求返回原任务；键相同而请求不同拒绝。任务状态为 queued/running/succeeded/failed/interrupted，查询结果持久化。明确重试使用原目标内容、最新线上基线和新执行尝试；成功任务不可重试。
- 切换完成、数据库登记前中断时，根据部署指针、attempt 身份和 manifest 校验补记成功；未切换则标记 interrupted，不自动重新发布。无法识别合法切换结果时停止新发布并报告。DB 内容仍是主数据，部署凭据只用于确认派生产物的运行事实。
- Astro 真实预览使用当前文章固定工作稿，其余文章和配置使用线上版本；包括新文章详情。预览产物不切换线上、不锁定公开身份，页面及所有资源仅认证用户访问。利用认证 fetch/受控资源或限定预览的短期凭据接入，不改变 JWT + DB Session 体系。
- 首次配置发布创建无文章站点基线，随后进行文章发布/预览。首版静态页面为文章列表、详情、分类、标签、404；站点不读取 CMS DB 或管理 API。
- 展示日期、保存时间与实际上线时间分开；默认时区 Asia/Shanghai，内部 UTC。未设置展示日期则冻结本次提交的默认日期，重试不漂移；线上更新时间只随成功发布变化。旧内容日期与更新时间保留。
- 文章须下线成功且无相关在途操作才可归档，未上线文章可直接归档。归档停止编辑但保留正文/历史/Slug；恢复为可编辑状态，不自动上线。不提供永久删除。
- 站点配置包括名称、简介、公开地址、语言、时区；作者配置包括名称、简介、头像。保存不发布，文章发布使用线上配置。
- 永久保留文章修订，不自动清理引用媒体。正式产物保留最近五次成功发布及当前使用版本，清理不能影响在途任务和恢复。私有预览/失败输入的清理可配置且同步解除产物引用。
- SQLite 默认并维护 PostgreSQL。追加配套逻辑迁移及菜单/权限种子，不改已应用迁移。保持统一 Taskfile 检查、两数据库集成验证和 CMS/Site 独立构建。
- 单向旧内容导入保留原文章和媒体路由、日期、多分类及标签，修正可解析相对文章链接；重跑不产生重复内容，冲突、不兼容和无法解析项明确报告。旧主题和布局不随导入迁移。

## Testing Decisions

- 优先在最高现有边界验证外部行为：通过认证 HTTP 请求与持久数据库验证操作，读取实际静态产物/公开 HTTP 与后台 UI 验证结果。避免测试私有函数、内部调用顺序或复制实现。
- 沿用现有 handler 合约、repository/事务、SQLite/PostgreSQL migration integration 和 embed/build 隔离测试模式；新增内容契约尽量共享双数据库测试用例。
- 主要测试接缝为“后台/API 提交操作 → 持久状态 → 静态读者结果”；发布中断另在 Builder/部署适配边界提供可控故障与进程重启，使用真实临时文件系统，断言结果而非内部步骤次数。
- Content 覆盖不完整草稿、手动/自动修订、版本冲突、修订不可变、恢复及归档；浏览器覆盖中文输入、保存状态、本地修改保留及上传/发布交互。
- Taxonomy/Media 覆盖多分类、身份冻结、历史恢复冲突、AST 引用及所有文件删除/状态入口；私有上传不可匿名读取，公开附件与图片来自批准的 release。
- Publishing 覆盖 A/B 只发布 A、提交后继续编辑、未发布配置隔离、重复请求、失败后其他任务成功再重试、校验/构建/切换失败、每个切换中断窗口重启和未知指针状态。
- Preview 覆盖新文章真实详情、其他草稿隔离、未授权页面/资源拒绝及无线上副作用；认证机制通过实际浏览器请求验证。
- Site 覆盖完整聚合入口、下线移除、Markdown 渲染契约、静态媒体独立访问；CMS 停止后站点与媒体仍可读。真实迁移的旧 URL 编码和渲染结果需要专门验收。
- 通过 Taskfile 执行适用检查及统一 task check；保持 Astro 故障不影响 CMS、Admin 故障不影响独立站点构建。运行环境阻碍明确报告，不能以 mock 或放宽 DoD 代替真实验收。

## Out of Scope

- 多作者、协作审稿、部门内容组织、独立页面。
- 富文本模式、MDX、公式、Mermaid、可执行正文组件/HTML、修订差异比较。
- 定时发布、永久删除文章、整站一键回滚。
- 发布后修改文章 Slug、已公开分类标签改名及自动重定向。
- 旧主题/布局迁移、搜索、评论、RSS、导航编排、高级 SEO、主题切换。
- 远端部署平台、MQ、自动抓取/代理外部媒体、将上传目录直接公开。
- Markdown 双主数据、Git 发布内容、Astro 嵌入 CMS 二进制。
- 本次发布 Spec/Tickets 不包含业务实现、源码推送、部署或关闭父 Issue。
