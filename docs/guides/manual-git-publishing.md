# 手动推送 Git 输入并用 Actions 构建

本地发布、预览和静态站点服务继续独立运行。Git 推送只提交已成功发布的整站输入，不发布工作稿，也不表示远端构建或部署成功。

## 配置

1. 在 GitHub 创建公开输入仓库。本项目验收目标为 `EziosWJ/CMS_PRE`，源码仓库为 `EziosWJ/cms-golang-astro`。
2. 更新程序前备份数据库和运行目录，停止 API/执行器，使用迁移工具显式执行 schema 与 seed，之后启动 API。新增 schema 15/16 和 seed 10，SQLite/PostgreSQL 均维护。API 不自动迁移。
3. 管理后台打开 **GitHub 连接**，填写 fine-grained PAT，限定输入仓库，授予 Contents 读写。检测连接，选择仓库和已有目标分支；空仓库使用其默认分支。
4. 选择公开 CMS/Astro 源码仓库和分支或标签。源提交必须包含输入校验脚本和工作流模板；每个推送任务解析并固定确切 SHA，未提交的本地模板改动不会进入远端构建。
5. 保存连接。Token 不回显、不保存在浏览器；只能通过重新填写替换。检测连接证明认证和仓库访问，不等于保证细粒度 Token 的 Contents 写权限或分支保护允许实际提交。
6. 把 `templates/github-actions/build-site.yml` 复制到输入仓库 `.github/workflows/build-site.yml`，将触发分支改为所选目标分支。由用户安装工作流，CMS 不需要 Workflows 写权限。若仓库为空，可先推送一次初始化，再安装模板。用 API 或 `git push` 写入 `.github/workflows/` 需要额外权限：经典/OAuth Token 需要 `workflow` scope，细粒度 PAT 需要 `Workflows: Read and write`；缺少时 GitHub 返回 404 而不是 403，所以推荐在网页端 New file 粘贴模板并提交。

## 推送与构建

在 **发布与预览任务 → 手动 Git 推送** 点击“推送当前已发布站点”。记录包含本地 Release、源码 SHA、状态、尝试和提交链接。没有可信的成功版本时，先在本地发布站点配置。

任务固定创建时的成功版本；后续本地发布不改变它。运行中不能修改目标或断开连接。失败或中断使用“重试原输入”，若已有较新成功推送，旧任务会标记已被取代。网络响应未确认时重试同一请求，不新建操作。

输入存放在仓库 `cms-input/`：公开 manifest JSON、Markdown 正文副本、引用媒体及别名、版本 1 的 export 元数据。JSON 驱动 Astro。CMS 只替换这个生成目录并删除过时生成文件；人工文件和工作流保留。不反向导入远端文章。

完全空的仓库需要先通过 Contents API 创建初始 export 元数据提交，再由 Git Database API 完成完整输入提交；CMS 记录任务和执行尝试，响应丢失时进入中断，明确重试先读取远端。初始化提交不表示完整输入已推送。

内容与源码不变、且远端完整生成目录一致时，不产生空提交；重新运行构建请使用 GitHub Actions 的重跑入口。

模板检出事件输入提交与固定源码，按源码 Node 版本和锁文件安装，校验契约/摘要/每个文件，清除源码自带公开资源后复制输入媒体，全量构建一次并上传静态 artifact。并发运行保留同分支最新执行；原始 JSON、日志、密钥和内部产物 marker 不进入静态输出。构建成功目前只生成 artifact，GitHub Pages 与 Cloudflare 自动部署留待下一阶段。

## 运行数据与恢复

运行目录下 `git-export/` 包含加密连接所用 `master.key`、独立执行器锁以及各任务私有输入副本。根密钥为 32 字节，目录 0700、文件 0600；备份必须同时覆盖数据库和主密钥。主密钥丢失时不会静默覆盖已有密文：先断开连接，再输入新 Token 重新连接。

尚未完成私有副本校验的任务保护源 Release，维护清理不能删除它。私有副本准备完成后解除源保护。成功/已被取代的副本超过七天可自动清理，失败/中断副本保留供重试，历史与密钥不随之删除。

重启后先核实持久化计划提交是否已经进入远端分支历史：已进入则补记成功；未进入或无法核实时保持中断，等待明确重试。GitHub 失败不会改变本地发布基线或站点指针。

## 检查与常见失败

- Token 失效或仓库权限不足：替换 Token，检查是否限定了正确仓库及 Contents 读写权限，再重试原任务。
- 分支保护或远端竞争：CMS 非强制更新，最多三次冲突重试；不强推或回退输入。
- 安装模板返回 404：这是凭据缺少工作流写权限的平台行为，不代表仓库不存在（仓库不存在同样返回 404，可先用检测连接区分）。改在网页端添加 `.github/workflows/build-site.yml`，或给凭据补 `workflow` scope / `Workflows: Read and write`。
- 资源缺失或哈希不符：恢复源发布资源或私有输入副本，不从最新工作稿重生成旧任务。
- Actions 提示源码脚本缺失或主题版本不匹配：先提交并发布对应源码，再选择兼容分支/标签推送新任务。
- CI 状态在 GitHub 查看，CMS 不轮询、不回调、不标记平台上线。

代码验收使用 `task check`、SQLite/PostgreSQL 集成检查，以及 opt-in 的浏览器脚本；复用 Playwright 1.63.0 和 Chromium 153.0.8010.12，禁止安装新版本。
