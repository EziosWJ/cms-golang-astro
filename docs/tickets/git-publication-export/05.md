## What to build

作者将提供的 Actions 模板安装到输入仓库后，手动推送自动构建 Astro，获得可供下一阶段平台部署使用的公开静态站点 artifact。

## Acceptance criteria

- [ ] 提供输入仓库工作流模板与页面安装说明；所选目标分支 push 自动触发，可在 GitHub 手动重跑；CMS 不写工作流，不需要跨仓库 dispatch。
- [ ] 按输入元数据检出公开 CMS/Astro 源码的确切 SHA；校验契约版本、路径边界和文件校验和，不跟随源码分支的最新提交。
- [ ] 遵循源码声明的 Node 版本及锁文件安装，隔离输入资源与源码自带 public 文件，JSON 驱动 Astro，Markdown 不成为主数据源。
- [ ] 构建一次并上传静态 artifact；不包含原始输入 JSON、内部 Release 标记、CMS 日志、凭据或服务端存储路径；所有文章与引用媒体可访问。
- [ ] 处理工作流并发并说明过期执行行为；页面提供提交和 GitHub 构建入口，CMS 不轮询或回写 CI 状态。
- [ ] Comic 与 Vaporwave 使用真实导出 fixture 完成校验、构建和 artifact 检查；故意修改输入校验和或使用不兼容版本时明确失败。
- [ ] 提供公开仓库、最小 PAT、工作流安装、源码提交、重新运行和故障排查文档；明确 GitHub Pages/Cloudflare 部署以及域名/base 适配属于后续阶段。
- [ ] 执行适用 Taskfile 检查，记录一次安装模板后 push 触发的实际 Actions 验收；若外部环境未配置则明确标为未完成，不把本地模拟当远端成功。
