# [Ticket Git-01] 提取可移植发布输入准备，保持本地发布与预览兼容

GitHub：[#52](https://github.com/EziosWJ/cms-golang-astro/issues/52)

## Parent

https://github.com/EziosWJ/cms-golang-astro/issues/51

## What to build

先分离不依赖 Node 的发布输入准备与 Astro 执行，让现有本地发布和预览继续完整运行，为后续手动 Git 推送提供可复用输入。此任务是必要的预重构例外，不新增占位页面或远端发布行为。

## Acceptance criteria

- [ ] 通过已有发布与预览入口验证重构前后的作者可见行为一致；保持本地成功条件、站点指针、失败恢复和构建解耦。
- [ ] 定义版本化公开输入契约：JSON 驱动渲染，Markdown 为可读副本；只导出固定已发布快照中的文章、分类、标签及站点配置。
- [ ] 公开 DTO 排除服务器存储路径、内部用户、审计及凭据；媒体仅包含被引用的资源与所需别名，保留现有公开 URL 语义。
- [ ] 导出元数据包含 schema 版本、文件校验和及稳定输入身份；与时间、随机任务 ID、内部 Release ID 解耦，为后续附加源码 SHA 留出明确接口。
- [ ] 以真实输入准备、数据库和媒体验证缺失与损坏资源、未发布内容排除、确定性导出；Comic 与 Vaporwave 的既有本地发布和预览均通过。
- [ ] 执行适用的 Taskfile 后端与站点检查；明确记录未执行检查及原因。

## Blocked by

None (can start immediately).
