# [Ticket Git-03] 手动推送当前已发布输入并查看独立记录

GitHub：[#54](https://github.com/EziosWJ/cms-golang-astro/issues/54)

## Parent

https://github.com/EziosWJ/cms-golang-astro/issues/51

## What to build

作者从站点发布入口手动推送当前成功发布的整站输入，并在独立记录中查看固定版本、进度与 Git 提交链接；本地发布与预览继续独立工作。

## Acceptance criteria

- [ ] 创建任务时固定可信的当前成功发布版本及源码 SHA；没有可靠基线或源码无法解析时拒绝，不采用草稿或尚未发布配置。
- [ ] 完成任务及执行记录迁移、API、独立队列、后台入口和历史详情；连接管理、推送、查看权限分别生效。
- [ ] 固定发布版本并保护其不被清理；从已验证的 Release 公开文件制作私有输入副本并校验资源身份，网络期间不长期占用站点发布锁。
- [ ] 使用 Go GitHub REST Git Database API，无 Git CLI 依赖；空仓库首次推送及已有分支推送都得到可查看提交。
- [ ] 只管理约定的生成输入根目录，保留工作流、README 和其他文件；删除已经过时的生成文件；提交包含公开输入契约、文件校验和和确切源码 SHA。
- [ ] 同一目标分支串行执行，提交前持久化计划提交 SHA，非强制更新引用；基础冲突有限重试，无法确认远端结果时显示中断且不盲目重推。
- [ ] 任务固定目标配置；活跃任务期间禁止切换目标或断开连接，凭据轮换不改变任务目标；推送失败不改变本地发布状态或当前站点。
- [ ] 历史展示排队、运行、成功、失败和中断，附输入版本与提交链接；只声明 Git 推送结果，不声明 CI 或部署成功；本任务不暴露尚未实现的重试操作。
- [ ] 从 API 入口用真实数据库、导出及任务执行验证首次和增量推送、保留非生成文件、排除草稿、媒体完整、发布并发及本地失败隔离；模拟的仅为外部 GitHub，验证后台作者流程。
- [ ] 执行适用 Taskfile 检查和 SQLite/PostgreSQL 迁移验证，记录结果。
