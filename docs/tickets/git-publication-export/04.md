# [Ticket Git-04] 安全重试与核实中断，避免重复提交和旧版本覆盖

GitHub：[#55](https://github.com/EziosWJ/cms-golang-astro/issues/55)

## Parent

https://github.com/EziosWJ/cms-golang-astro/issues/51

## What to build

作者可以在记录页面安全重试失败或中断任务；重复输入返回已有提交，旧任务不会覆盖已经推送的新版本。

## Acceptance criteria

- [ ] 补齐重试接口、执行记录及页面操作；重试使用原任务固定输入与源码 SHA，目标不能被当前连接配置偷偷替换。
- [ ] 内容与源码身份均不变时返回已推送及已有提交链接，不制造空提交；重新运行工作流引导到 GitHub。
- [ ] 更新引用响应丢失或进程重启后，核实持久化计划提交及远端引用的祖先关系；已成功提交即恢复成功状态，不重复创建或覆盖。
- [ ] 同目标较新任务已成功时，旧任务标记 superseded 并拒绝重试，引导推送当前版本；禁止强制推送或回退输入。
- [ ] 验证远端人工提交、并发引用变化、有限冲突重试以及失败/中断/已取代状态在页面可理解，禁止盲目无限重试。
- [ ] 成功或已取代任务的私有输入副本超过 7 天可清理；失败和中断任务保留可重试副本；保留历史及主密钥，释放发布版本保护不会破坏已固定输入。
- [ ] API 级故障注入覆盖远端实际成功但响应丢失、重启恢复、源码不同、内容相同、重复输入及旧任务重试；使用真实数据库和输入副本，仅模拟 GitHub。
- [ ] 执行适用 Taskfile、数据库兼容与既有浏览器验证，记录结果。
