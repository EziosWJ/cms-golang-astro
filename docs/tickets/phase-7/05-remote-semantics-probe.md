## Parent

[ADR-0009](../../adr/0009-site-config-collection-and-remote-delivery.md) 决策三；阶段说明见 [README.md](README.md)。

本 Ticket 为本地新建，**未创建远端 Issue**。

## What to build

**先实测，再写代码。** 用本地已构建的产物手动部署到 Cloudflare Pages 测试项目，把 404、trailing slash、`_headers` 生效与缓存分级的**实际行为**测出来并记录，作为 P7-08 / P7-09 的输入。

理由：本地站点由 Go 静态服务提供（标记文件驱动、显式 404 状态、`http.ServeContent` 且无 `Cache-Control`），远端由 CDN 提供，两者对目录式 URL、404 页面与缓存的默认行为并不同构；把假设直接写进实现会固化成线上事故。

本票是**能否决既有假设的前置门**：若实测结论与 ADR-0009 决策三冲突，回到 ADR 修订，而不是就地变通。

## 需要用户完成的准备（未完成前本票不可执行）

账号侧准备按 ADR-0009 决策三归作者，本票**依赖**它们。缺任一项时本票应停在「待准备」，**不得**把未执行项标为通过（参见 Phase 1 的「环境验收延期」先例）。

- [ ] Cloudflare 账号可用。
- [ ] 一个以 **Direct Upload** 方式创建的 Pages 测试项目（不是 Git integration；选定后不可改回）。
- [ ] 具备 **Pages:Edit** 权限的 API token（最小权限，不要账号级管理权限）。
- [ ] 本机可用的 `wrangler` 与 Node 运行环境（版本需记录）。
- [ ] 已确认测试项目的**生产分支名**，用于两阶段验证。

## Acceptance criteria

- [ ] 用手动方式（`wrangler pages deploy` 或等价手段）把一份**现有**产物部署到测试项目。本票**不写产品代码**、不改仓库中的实现；只新增一份实测记录文档。
- [ ] 实测并记录：目录式 URL 的规范化行为（`/archives` 与 `/archives/` 各自返回什么、是否重定向、重定向状态码）；`trailingSlash: "always"` 下的实际结果。
- [ ] 实测并记录：根 `404.html` 是否被自动用作 404 页面、自定义 404 的**实际 HTTP 状态码**、深层路径未命中时的行为。
- [ ] **`_headers` 在部署副本中手写一份**（写进部署目录，**不进产品代码、不提交仓库**），把手写内容一并记入实测记录。现有产物**不含** `_headers`，它由 P7-08 生成，所以只能用这份手写的来测。实测并记录：`_headers` 的生效范围与优先级、能否覆盖 `Cache-Control`、可用的匹配语法与限制。
- [ ] 实测并记录：手写的 `_headers` 文件本身是否可被公开取到（本地 `staticweb` 会供应产物中的任意文件，远端是否不同）。
- [ ] 实测并记录：点号开头的路径（如 `.release.json`）在远端是否可被公开取到——本地显式拒绝，远端预期不拒绝。
- [ ] 记录本仓库产物与远端限制的差距：文件数与单文件大小上限的实测结果。
- [ ] 记录产物中带内容哈希的资源与 HTML 各自当前的实际缓存行为。
- [ ] 结论写入一份可复核的记录（`docs/specs/` 下的实测记录），并明确列出：**哪些结论否定了 ADR-0009 决策三中的假设**、哪些需要新增实现约束。
- [ ] 记录中写明账号侧准备的实际状态（哪几项已完成、哪些未完成）与执行日期。
