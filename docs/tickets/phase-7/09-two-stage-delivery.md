[ADR-0009](../../adr/0009-site-config-collection-and-remote-delivery.md) 决策三（触发与串行、两阶段、失败语义）；阶段说明见 [README.md](README.md)。

## What to build

两阶段交付执行、四条失败语义，以及后台的手动交付入口。

**本 Ticket 起才需要真实凭据与网络。** 预部署阶段改称「预部署」，不得与认证私有预览共用「预览」一词。

## Acceptance criteria

- [ ] **手动触发**：不排队、不自动、不由内容发布连带触发。同一站点已有在途交付时**明确拒绝**并提示等待（不排队）。
- [ ] 交付**抢 local runtime root 的锁**，同一时刻只有一个 Astro 构建；等待锁不产生假进度。
- [ ] 交付**不得进入 `Worker.Run` 的持有链**：验证「本地被 `blocked_reason` 阻塞时，远端交付仍可进行」以及「远端交付失败/待核实**不阻塞**本地编辑与本地发布」两条断言。此为「互不影响」唯一需要真正落地处。
- [ ] **两阶段**：先以代码中固定的非生产分支创建部署得到预部署地址，对其做**真实 HTTP 冒烟**（首页、一篇文章页、一个 404、一个聚合页、一个带内容哈希的资源），通过后再以站点配置的 `productionBranch` 提交**同一份 manifest**。
- [ ] 两阶段使用**同一份 manifest 与同一产物**；第二次提交按内容哈希去重，不重传文件。
- [ ] 成功边界是**「生产部署生效」**；仅构建成功或仅提交成功**不记为交付成功**。状态文案须表达实际完成的阶段。
- [ ] 失败语义（四条，逐条有测试）：预部署通过而生产提交失败 = **部分成功**（线上仍为上一版，内容已验过），重试**固定原内容快照**；结果不可知 = **待核实**，查询该站点当前生产部署核实，不一致时**阻塞该站点后续交付且不自动重试**；进程被杀导致在途交付 = 重启**不自动重发**，记为需显式重试；**不提供取消**。
- [ ] **基线媒体不可用时的明确失败**：若交付基线已不再是 local 当前线上版本**且**其引用的媒体确实不可用，交付**明确失败并给出可操作提示**，不得表现为随机错误（媒体引用保护的机制见 ADR-0009 决策三与 P7-06）。
- [ ] 后台入口与交付记录展示：触发、查看阶段与结果、显式重试；「待核实」与「阻塞」的原因与下一步可见，**不把等待误报为正在构建**。
- [ ] 站点停用后不得再发起交付；停用**不等于**下线远端站点（下线是独立动作，不在本 Ticket）。
- [ ] 交付记录全程可核实：能回答「远端线上现在是哪一份、由哪个内容快照与哪份站点配置生成」。
