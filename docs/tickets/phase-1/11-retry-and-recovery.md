## What to build

作者能查看失败或中断原因并明确重试原任务；其他文章后来已成功发布时，重试不会撤回它们。服务器意外重启后任务状态与实际读者站点一致。本票扩展已有原子切换闭环，不重新制造发布管线。

## Acceptance criteria

- [ ] 查询页/API 显示任务与各次尝试、基线、错误及状态；允许失败/interrupted 任务明确重试，成功任务不可重试。
- [ ] 重试用新幂等键追加尝试，网络重发不重复追加；固定原所选修订，但采用最新成功 release 基线。
- [ ] 故障任务之后其他任务成功，再重试前者，其他更新仍在线；继续编辑的目标文章也不会混入新内容。
- [ ] 提交和执行均重验生命周期、Slug/组织身份及媒体；旧固定内容失效时说明原因并要求新任务，不偷偷换版本。
- [ ] 通过可控故障+进程重启覆盖构建、校验、切换前、切换后记账前、登记成功后等边界；旧站点或完整新站点可读，不出现半份产物。
- [ ] 已切换且 manifest/attempt 合法时补记成功；未切换则 interrupted，不自动重新发布；未知指针报告并停止新发布。
- [ ] 任务串行和站点执行锁经重复/并发提交验证；worker 重启与 API 可用性解耦，超时、缺失 Node、磁盘失败有持久化原因。
- [ ] 以认证 HTTP/后台操作、真实临时文件系统与静态结果测试，而非内部步骤次数；执行双数据库和适用检查。
