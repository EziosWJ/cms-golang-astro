## What to build

作者可以区分即时预览与真实网站效果，明确发布的目标，并从任务结果继续操作。

实现包括必要的界面、API、权限与错误恢复，不把任务限定为样式改动。沿用既有领域不变量，实际检查当前接口后选择最小实现。

## Acceptance criteria

- [ ] 网站预览固定快照、认证访问，修改后标记过期，按需更新，不改线上指针。
- [ ] 发布字段错误可定位；确认后先完成上传/保存，再固定目标，失败不提交。
- [ ] 固定后可继续编辑，任务成功不把后续工作稿误标已上线。
- [ ] 显示真实排队/执行/成功/失败/中断及执行器阻塞原因；离开重开可找到目标和结果。
- [ ] 成功提供查看文章；失败说明可核实的线上状态，不对未知指针假报原站安全。
- [ ] 重试原固定目标与发布最新修改区分；串行、请求幂等、其他工作稿/配置隔离不变。
- [ ] 发布记录以标题/操作/结果/时间为主，内部数据与暂停恢复保留于诊断/维护区域。
- [ ] 更多操作包含下线/归档/恢复确认，只有成功下线改变公开状态，恢复不自动上线。
