## What to build

以自动化、真实浏览器和目标用户试用证据决定本阶段是否达到日常使用标准。

实现包括必要的界面、API、权限与错误恢复，不把任务限定为样式改动。沿用既有领域不变量，实际检查当前接口后选择最小实现。

## Acceptance criteria

- [ ] 逐项记录 Spec §9 的环境、步骤、观察结果、证据与未执行原因，覆盖前面各票而非仅冒烟。
- [ ] 桌面/平板/手机与键盘完成核心流程，保存/冲突/上传/配置/发布故障使用隔离 runtime。
- [ ] 执行 task check；后端变更双数据库合约，嵌入构建边界变更追加 task build:check；复用固定 Playwright/Chromium。
- [ ] 至少一位未参与开发且符合画像的用户仅收到任务目标，独立完成首次含图发布、修改隔离、预览更新和失败恢复。
- [ ] 记录求助与阻断，修复后复验；真人未执行则保持待验收，自动化不替代真人。
- [ ] 更新本阶段实施/验收记录；前阶段未验收项保留原状态，不以 Phase 2 通过宣称生产就绪。
