# [Ticket Pages-01] 模板增加 Pages 构建与部署，并提升动作版本

GitHub：[#59](https://github.com/EziosWJ/cms-golang-astro/issues/59)

## Parent

https://github.com/EziosWJ/cms-golang-astro/issues/58

## What to build

在已交付的输入仓库工作流模板上增加 Pages 部署，让 push 触发的构建直接发布为公开站点：构建作业产出 Pages artifact 并保留可下载产物，部署作业在 `github-pages` 环境发布；权限只在部署作业追加。同步把模板内 Actions 提升到当前稳定 major，消除 Node 20 弃用警告。固定源码检出、输入校验与静态边界检查保持不变。

## Acceptance criteria

- [ ] `templates/github-actions/build-site.yml` 的 build 作业用 `upload-pages-artifact` 产出 Pages artifact，并保留 `upload-artifact` 供下载；新增 deploy 作业声明 `environment: github-pages` 并用 `deploy-pages` 发布。
- [ ] 权限最小化：构建作业保持 `contents: read`，只有部署作业追加 `pages: write` 与 `id-token: write`；不新增 CMS 侧权限或接口。
- [ ] 并发与失败语义：构建沿用现有并发组与取消策略，部署使用独立并发组；失败或取消保留上一次成功部署，不提供文件复制式旁路发布。
- [ ] 模板内 Actions 使用当前稳定 major（`checkout`/`setup-node`/`upload-artifact` `v7`、`configure-pages` `v6`、`upload-pages-artifact`/`deploy-pages` `v5`），构建日志不再出现 Node 20 弃用警告；源码仓库自身 `.github/workflows` 不在本任务范围。
- [ ] 既有行为不回归：固定源码 SHA 检出、输入 schema/路径/校验和校验、隔离公开资源、全量构建一次与静态输出边界检查继续有效。
- [ ] 记录模板改动说明与用户的安装/更新步骤；执行适用 Taskfile 检查（含 `task check`），记录未执行项及原因。
