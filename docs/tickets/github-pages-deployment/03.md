# [Ticket Pages-03] 站点公开地址与已知缺口一致性

GitHub：[#61](https://github.com/EziosWJ/cms-golang-astro/issues/61)

## Parent

https://github.com/EziosWJ/cms-golang-astro/issues/58

## What to build

核对部署地址与站点公开地址的一致性，并记录本阶段不处理的既有缺口，避免把已知 404 当成配置错误。公开地址不一致会让 canonical 与绝对链接指向错误位置。

## Acceptance criteria

- [ ] 在 CMS 站点配置中把 `publicUrl` 设为实际部署地址（或确认其已正确），并核对构建产物中的 canonical 与绝对链接指向该地址。
- [ ] 记录 base 与 `publicUrl` 的关系，以及切换域名时的两步操作（改仓库变量、改站点公开地址）。
- [ ] 记录已知缺口：主题声明但不生成的 RSS/Sitemap 请求为 404；站点配置模型缺少旧站副标题、社交链接与页脚许可字段；明确本阶段不实现，也不记为通过。
- [ ] 若公开地址不一致会造成读者可见错误（错误 canonical、跨域断链），修复或明确列入差异，不静默忽略。
- [ ] 执行适用 Taskfile 检查，记录未执行项及原因。
