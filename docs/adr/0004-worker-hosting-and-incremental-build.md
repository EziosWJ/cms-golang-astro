# ADR-0004：worker 默认内置与部分构建边界

状态：执行器托管部分 Accepted（2026-10-04，见 Issue #19）；部分构建与全站重建仍为 Proposed，不属于本次实现授权。

独立 worker 增加了单机作者的启动负担，因此拟改为 CMS 主程序默认托管 worker，同时保留关闭内置执行和独立 worker 模式；持久化队列、串行执行与独立 Node 构建子进程继续保留。部分构建首先复用未变化文章详情，重建全部列表、分类标签页面，并组成完整产物后原子切换；相较精确追踪所有页面依赖，这一范围优先保证一致性。全站重建使用已发布内容，不自动发布其他工作稿或未发布配置。

本决定接续 ADR-0003 的独立 worker 运行方式，不改变完整产物及成功切换的发布边界。执行器托管的完整运行边界以 [已确认规格](../specs/embedded-publication-worker.md) 为准；部分构建提案仍需另行确认。

## 已确认策略

- worker 故障不终止编辑服务。普通构建失败只影响该任务；严重异常暂停发布并明确显示原因，不允许任务长期伪装成正常等待。
- 关闭 CMS 时停止接新任务，给予当前任务 30 秒收尾，超时取消构建并记录中断；已经切换站点的任务通过既有恢复机制补齐登记。重启不自动重新发布中断任务。
- 首次发布全量构建。模板源码、样式、渲染规则、依赖或已发布站点配置变化自动转为全量构建，并显示实际执行模式与原因。
- 部分构建采用明确的模板约定：文章详情只能依赖自身内容、站点配置及对应媒体。跨文章内容放入统一重建的列表页；需要跨文章依赖的自定义详情模板使用全站构建。
- 私有预览保留全量构建，本轮不复用正式页面，避免认证路径与资源地址混用。

## 已接受的执行器运行边界

默认主程序内置 worker，可通过 publication.worker_enabled 关闭；保留独立 worker 命令，公开静态服务仍独立。两种执行器与维护工具共用站点锁。内置执行器拿不到锁不终止编辑服务；临时基础设施故障退避恢复，未知指针保持阻塞。

后台可暂停和恢复：暂停停止领取，待当前任务结束后释放锁；只有 paused 才可以维护。暂停期间任务可以入队，恢复时重新取得锁并核对发布状态。维护暂停是进程状态，不跨重启保留，维护期间必须避免 CMS 自动重启。

缺少构建环境时允许继续编辑，拒绝新增发布、下线、配置发布及 Astro 预览任务；保留既有队列，修复后自动继续。已切换站点的中断任务核对后补齐记账，未切换的任务要求明确重试。

## 仍待确认

部分构建优化、全站重建操作及内容时点仍属 Proposed，本次没有实施。
