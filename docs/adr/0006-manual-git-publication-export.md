# ADR-0006：保留本地发布，新增手动 Git 中间产物推送

状态：Accepted（设计决策）；作者已授权发布，规格 [#51](https://github.com/EziosWJ/cms-golang-astro/issues/51) 与任务 #52–#56 已创建，代码实施已获授权，验收状态见配套验证记录。

2026-10-10 讨论已明确：保留现有同机 Astro 构建、发布及静态服务；GitHub Actions 作为另一路可选渠道，由作者手动推送中间产物启动。下一步优先落实 Git 中间产物推送，不把现有本地执行器替换为远端构建执行器。

CMS 数据库继续作为内容主数据源。新增 Git 用途是传输派生的构建输入，不成为文章编辑或回写的数据源；这是对 ADR-0001 中 Git 仅管理源码边界的已接受扩展，不修改 ADR-0003 的本地发布成功条件。

推送成功只表明指定输入已提交到目标 Git 仓库，不能据此标记远端构建或平台部署成功。CI 是否自动执行取决于工作流所在仓库及触发配置；向中间产物仓库推送不会自动触发 CMS 源码仓库的工作流。

## 已确认的输入与触发边界

作者手动推送当前本地已成功发布站点的完整快照，不选择未本地发布的文章修订，也不包含工作稿或尚未发布的站点配置。推送对应的本地版本在任务创建时固定；后续本地发布不改变这次推送的来源。

轻量 CI 工作流位于中间产物仓库，由目标分支的 push 事件触发；工作流检出固定版本的 CMS/Astro 源码进行构建。无需由 CMS 额外触发源码仓库的跨仓库工作流。

上述边界的实施细节见 [首阶段规格](../specs/manual-git-publication-export.md)。GitHub Pages 与 Cloudflare 的部署完成条件留待对应阶段决定。

## 已确认的使用入口与仓库可见性

首版在管理后台提供站点级手动推送入口和独立推送记录，与文章发布操作分开。中间产物仓库使用公开仓库，后续可在同仓库配置 GitHub Pages；导出限定已发布内容与公开媒体，移除服务器存储路径、内部用户及审计信息。

仓库与授权配置通过管理后台完成，减少作者手动编辑服务器 Git 配置的负担；不采用先前建议的纯服务器配置方式。

## 已确认的 GitHub 连接与同步范围

首版仅支持 GitHub。管理用户在独立的 Git 连接页面填写 Token，检测连接并选择仓库和目标分支，无需手工修改服务器 Git 配置；暂不引入 GitHub App/OAuth 授权登录。

远端拉取仅用于读取仓库、保留现有工作流并在目标分支基础上提交派生内容，不把远端文章修改导回 CMS 数据库。仓库内的发布输入由 CMS 生成，CMS 数据库仍是唯一内容主数据源。

GitHub 凭据不得进入公开站点配置、构建输入、Git URL、操作日志或普通配置读取响应。现有系统配置为明文存储与读取，不能直接复用为凭据存储；采用独立连接配置与只写凭据接口。

## 已确认的首阶段范围与版本固定

首阶段实现页面 GitHub 连接、手动推送与独立推送记录，并提供由用户放入中间产物仓库的 Actions 构建模板，验证自动构建。GitHub Pages/Cloudflare 的部署、部署状态回写以及服务器无 Node 改造不在首阶段范围内。

页面允许选择 CMS/Astro 源码仓库的分支或标签。每次推送时解析为确切提交 SHA，并与固定的内容快照一起记录，远端构建按该 SHA 检出源码；未提交的本地模板改动不会隐式进入构建输入。

内容快照与选定源码版本均未变化时，不制造空提交，返回该版本已经推送及已有提交链接。工作流重新运行由 GitHub 提供，不以重复推送模拟远端重试。

## 已确认的仓库准备、重试与结果展示

作者先在 GitHub 创建公开仓库，再在 CMS 页面选择现有仓库。CMS 首阶段不提供创建仓库功能，保留仓库中的工作流和非生成文件。

失败任务重试原来固定的输入；若同一目标已经成功推送更新版本，则拒绝旧任务重新覆盖最新输入，并引导推送当前版本。不提供强制推送或旧输入回退功能。

首阶段只记录 Git 推送状态、固定版本与提交链接，CI 构建结果由用户在 GitHub 查看；不实现 Actions 轮询、回调或远端平台部署状态回写。
